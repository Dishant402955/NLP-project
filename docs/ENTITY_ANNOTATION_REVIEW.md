# Entity annotation review: assistant-reviewed proposals

**Purpose:** Human-review aid for the 66-row targeted entity benchmark. This document contains assistant-reviewed proposals, not gold labels. Do not use it as confirmed annotation until the project owner approves or corrects every row.

**Annotation contract:** Exact source text; zero-based Python character offsets; exclusive end; offsets into the original request after outer whitespace trimming. `request[start:end]` must equal the recorded value. Overlaps are allowed, including a filename/path with its extension. Empty lists mean no supported entity is proposed.

**Review method:** One pass over all AI suggestions, followed by a consistency pass for exact spans, unsupported entity types, false path fragments, filename/extension overlap, date/condition separation, and scope phrases incorrectly treated as comparisons. Reference Bash commands and extractor predictions were not used.

**Important review limitations:** The sample is targeted, not prevalence-representative. Some proposals are judgment calls where the annotation guide does not fully specify edge cases (notably a symbolic `>` comparison, duration variables, generic memory usage, and whether path basenames also receive `file_name`). Please review these carefully.

## Items requiring particular human attention

1. **False positives removed:** `files/` fragments from `files/directories`; `below` when it means recursive search scope; `.com`/`.COM`/`.example.com` in host names; `.scripts` as a folder suffix; `.note` as an explicitly named dotfile; `.npm` from the directory `.npm-global`.
2. **Filename overlaps added:** Explicitly named archive/input/output files and path basenames are proposed as `file_name` alongside path and/or extension entities. Confirm that this is the intended gold-label convention.
3. **Temporal values added:** `each 30 seconds`, `$DAYS_TO_SAVE days`, and `a day ago` are proposed as `date_time`.
4. **Coverage gaps:** Generic memory usage in the process request is not assigned `process_metric`, because the documented type distinguishes virtual memory, resident memory, and CPU usage. User identifiers, directory names, and arbitrary command patterns are not represented by a dedicated supported entity type.
5. **Symbolic comparison:** `>` in the 100 MB threshold request is proposed as `comparison_condition` with normalized value `greater_than`; the current extractor rules are phrase-oriented, so this is a documented edge case, not a claim about current extractor behaviour.
